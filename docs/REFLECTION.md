**Reflection**

The biggest challenge with this project was taking something that already has a lot of variety, like a weather app, and figuring out where the market's shortcomings are. I spent a lot of time brainstorming what would be cool to do. 

I am really happy with the way I structured the code so that each view just has a Helper file, which has functions that can be called in the main "performers" which makes it easier to get a better understanding of the code in a whole, I just think of the views as multiple performers, which makes it easy to navigate with ctrl+find/click since I have also introduced specific naming conventions Prefix_Action, so it should be descriptive of what each function does. I thought the API get sequence and the parser were great and I do like the dynamic layout of the views depending on time of day and year.

I am not sure exactly what I have learned but it was a good iteration after getting to know the spec files in lab B1 so I was able to use them more efficiently now than before. I spent more time on architecture before starting, and then built the app in steps. That let me be more involved in the building process. I was able to step in earlier on the main functionality, instead of facing a fully built app with a lot of code to navigate through. Instead of just doing all the tests after each prompt I was able to do it in stretches, for example getting the search mechanics ready before focusing on the UI and making sure the keyboard was not in the way of the search suggestions on the Compare screen.

I am not sure I would do a lot differently, maybe just document less, I feel like there is a lot of documentation and a person would rather just read something like the README, but that is just how I feel about it. It gives a better overview of the process of building the app the way it was done now.

I am confident that I could explain all the logic, but I'm not sure I could go into detail with the tsx, files since they are mostly just a bridge between the code and the phone, but am confident I could talk through it all and have a clear idea of how the code is structured.

It surprised me how much easier the code was to read, and how little extra work it took to make that happen, by structuring it the way I am used to from working in UiPath on automation software, and by using clearer naming conventions.
